TEE (confidential VM) GPU servers federate Prometheus into the control-plane monitoring exactly like non-TEE workers, on **NodePort 30090**.

- Inside the VM, the `sek8s` repo's `ansible/guest/roles/chutes-gpu/templates/monitoring-values.yaml.j2` deploys Prometheus with `server.service.type: NodePort, nodePort: 30090` and `networkPolicy.enabled: false` — same as this repo's `chutes-gpu` role.
- The host bridge (`sek8s` `host-tools/scripts/network/setup-bridge.sh`) DNATs the whole NodePort range `30000:32767` TCP from the host's public iface to the VM (`192.168.100.2`). So `<tee-host-public-ip>:30090` reaches the VM's Prometheus with no extra config. (br0 = 192.168.100.0/24, gw .1, VM .2.)
- This repo's federation config is generated by `ansible/k3s/tasks/charts/templates/monitoring-values.yaml.j2` (rendered on the control node), feeding `prometheus.federation.clusters` consumed by `charts/chutes-monitoring/files/scrape-configs/metrics-federation.yaml`.

TEE hosts are provisioned by the separate `sek8s` repo, so they are listed in a `tee_workers` inventory group used ONLY for federation; `site.yml` provisioning plays exclude them via `all:!tee_workers`. Override `federation_port` per host only for a non-default Prometheus NodePort.
